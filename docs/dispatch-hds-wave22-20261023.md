## 三 活单①：65 格逐格四问

先从盘上取格清单，不要抄任何报告里的汇总：逐文件对比 `git show <第十三波归位提交>:tests/...` 与工作树当前文件，或用那两份报告 §三 的逐格表**回读原始 TRX 复核**。每格回答四问并列成一行表：

1. **有没有凭证**——它的单枚清洁红落在哪一份 TRX、哪一轮（文件名＋`<Counters>` 的 `failed` 读数＋红格全名＋红点行号）。
2. **是不是一双手**——写这一格判据的那一手，与取这一格红的同一轮，是不是同一个执行体（第十三波有一格是守门人在载体里补的，报告里点名过；逐格判，别整批署）。
3. **十一项字段齐不齐**——①文件:行 ②改前 ③改后 ④`git diff --stat` ⑤跑法整行 ⑥TRX 名 ⑦红格全名＋消息要点＋红点行号 ⑧还原命令 ⑨还原后 `git status --short` 行数 ⑩还原 SHA-256 ⑪当轮预检输出。缺哪几项就点名缺哪几项。
4. **清洁度**——那一轮是"只放这一枚突变的单枚轮"，还是"批次轮里顺带红"（批次红永远只证明"这几枚里至少一枚能打红这一格"，不得署成某一枚的归属）。

**分类口径**（四类，别混）：A＝单枚清洁红且字段齐；B＝单枚清洁红但字段缺若干（点名缺项）；C＝只有批次轮红、无单枚轮；D＝盘上找不到该格的任何红凭证。**必须区分"盘上没有那份 TRX"与"有 TRX 但那轮没把这格打红"**——前者是"无凭据可读"，后者是"读过且为否"，措辞不许互换，也不许把前者写成"没有凭证"。
