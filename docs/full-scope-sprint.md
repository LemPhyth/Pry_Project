## 2. 版本命名与产物规则

作者 2026-10-12 明令：本轮产物**不使用 1.0 版本号**。据此定案：

| 版本 | 含义 | 谁能用 |
|---|---|---|
| `v0.1.0` | 内部日常候选：装完就能天天用，坏了能恢复 | 只有作者本机 |
| `v0.2.0` | 早期用户候选：第 0 层缺陷清零、dogfood 记录成型后 | 2–3 位核心早期用户（§7.2） |
| `v0.3.0 …` | 按内测反馈递增 | 最多扩到总计 3–8 位 |
| `1.0.0` | **只在作者明确点头时启用**，点头须同时撤销本节的"不叫 1.0" | — |

每个版本的生成条件，缺一不可：

1. 从**受跟踪的某个提交**打包，工作树零改动；不得使用未提交工作区，不得分别构建"前端版/后端版"。
2. `scripts/package-release.ps1 -Version x.y.z`（win-x64，产 `lite`/`minimal`/`full` 三档 + `SHA256SUMS.txt`）。
3. 包内容过 §8 第 3 条：无模型权重、无数据库、无密钥、无日志、无开发缓存、无 `.local-notes/**`。
4. 解压到全新目录 + 设 `Pry__DataDirectory` 指向隔离数据目录，跑完 `docs/eval/minimal-loop-run-checklist.md` 的四条并留读数。
5. `CHANGELOG.md` 的**「已知未做」段落必填**，逐条列出当时真实未闭合的缺口（不许写成"完整功能"，也不许用"暂未优化"这类措辞掩盖）。

第 5 条是作者那句"绝对有大大小小的问题"唯一能被追着的形态：问题清单不写进包，就没人对它负责。打 tag 与回滚照 `AGENTS.md` 第 4 条——回滚用单独的 `git revert`，禁止 `reset`/`checkout`/`clean`。

**推送权仍在作者**：本文件所有刀序都不含 `git push`。
