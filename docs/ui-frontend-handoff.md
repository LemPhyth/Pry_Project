- 不覆盖工作区其他协作者改动，不复制后端模型策略，不直接读写数据库、模型目录或模型进程。Sample 中未定稿服装只作角色参考，不纳入正式界面素材。

## 2. 当前问题与设计目标

| 当前问题 | 设计目标 |
|---|---|
| 壁纸只覆盖消息滚动区，上下被实体色截断，形成横幅；裁切随中间容器尺寸变化 | 背景属于整个陪伴工作区，构图稳定，滚动不改变背景定位 |
| 壁纸被压暗，但助手正文仍直接叠在复杂图案上 | 图片氛围与文字可读性分别控制，避免靠整体加黑解决所有问题 |
| 头像目前打开角色选择，与计划中的互动手势冲突 | 头像固定承担当前角色互动，角色切换拥有独立且明确的入口 |
| 历史、新会话和输入框仍占据较强的结构地位 | 当前角色及其消息成为中心；历史和配置按需访问 |
| 模型选择仍局限于旧预设 | 从后端完整模型投影构建列表，支持本地刷新和自定义网络模型 |
| 新增 Embedding 尚无独立呈现 | 明确区分聊天生成与记忆检索用途，真实表达已发现和已启用的区别 |
| 单一紫色主题无法表达后续不同角色 | 保持应用组件语言稳定，让角色配色、背景与桌宠形成一致体验 |

## 3. 主窗口结构

```text
应用栏：Pry 品牌                  陪伴 / 角色 / 记忆             设置 / 窗口按钮
陪伴工作区（一个连续背景层）
  角色栏：历史入口       [互动头像] 角色名、状态 [切换角色]       新对话（次操作）
  内容区：按需展开的历史列表 | 居中消息阅读列
  输入区：                  附件预览、输入、互动辅助操作、发送
```

应用栏可以保持独立实体表面；角色栏、消息区域和输入区共享工作区背景。角色管理、记忆与设置进入安静的实体工作页面，保持全局导航，不把壁纸强行铺到配置表单下。

角色栏明确区分角色名、当前会话标题和真实角色/服务状态。没有角色状态契约时不虚构“在线”“正在想你”等动态状态；模型与连接诊断放设置页，故障时在当前操作附近提供恢复入口。

历史默认收起但入口常见，展开不遮挡当前角色和输入操作。新对话使用次级按钮，不与发送同时采用高强调样式。打开历史会话时以会话绑定的角色为准，不把历史对话悄悄改绑到新角色。

### 3.1 壁纸与阅读表面

1. 背景图片层放在陪伴工作区共同父容器，消息 ScrollViewer 只滚动内容。历史抽屉开关不改变背景参考尺寸。
2. 默认使用覆盖工作区的等比缩放；覆盖必然可能裁切，不能承诺完整显示整张图。裁切根据已保存的焦点与缩放参数计算，不能每次恢复为居中；读取已有外观字段并验证保存、重新打开后的往返一致性。
3. 输入区高度变化不应使壁纸跟随消息区重新裁切。窗口本身改变尺寸时允许按工作区重新计算构图。
4. 分开处理图片透明度、模糊和阅读表面。不得静默忽略已有模糊/显示设置，也不得把统一深色遮罩当成所有壁纸的解决办法。
5. 有复杂壁纸时，助手消息使用中性阅读底面；用户消息使用角色强调色的柔和底面。元信息也必须有可读的背景承载。无壁纸时可使用更轻的连续文本布局。
6. 角色栏与输入区采用局部稳定表面保护可读性，避免重新形成横跨整个窗口的两个厚重不透明横条。大范围毛玻璃、发光和多层边框不是默认方案。
7. 空图片、加载失败或角色资源缺失时回退到应用背景，不闪出其他角色的旧壁纸；当前会话和草稿继续保留。

验收使用用户提供的复杂壁纸类型，以及亮图、暗图、无图四种场景。不得只用纯色背景完成验收，也不得将用户图片加入公开测试资源。

### 3.2 头像互动与角色切换

- 单击头像：在头像附近打开动作面板，列出当前角色声明支持的动作。面板包括名称与文字动作，不用含义不明的图标代替“摸摸头”“抱一抱”。
- 快速双击：只执行一次戳一戳，不同时打开动作面板或执行其他动作。采用系统双击时间或统一阈值，具体手势处理由前端实现。
- 面板也提供“戳一戳”文字入口；键盘 Enter/Space 打开面板，Esc 关闭并归还焦点。双击不成为唯一入口。
- 当前头像旁设置独立的“切换角色”按钮；头像、名称和切换按钮不得包在同一个共享点击处理器中。
- 发起请求时绑定当时会话与角色上下文；切换后取消待触发手势，丢弃过期响应的界面更新，避免互动落到错误角色。
- 请求中显示短暂进度并阻止重复提交；冷却、无可用预设、服务失败显示文字原因，重试按后端幂等语义执行。
- 戳一戳随机预设、持久化及回复发送归后端。前端通过正式消息链路显示结果，不在本地直接生成助手消息。
- 角色管理页预留“互动”分组：动作目录与戳一戳预设编辑（新增、修改、删除、启用、排序），沿用角色配置覆盖规则。契约未冻结时只做独立开发预览，不上线看似可保存的空壳。

### 3.3 主动消息与角色体验

主动消息按角色正常发来的一条消息呈现，更新对应会话摘要和未读；不使用全屏弹窗制造存在感。用户正在查看旧消息时保留阅读位置，以“有新消息”入口引导，不强制滚到底。

非当前会话或窗口不活跃时，按通知设置显示未读、托盘或系统通知，不抢焦点；通知使用消息所属角色的名称和头像。设置页准备主动话题总开关、频率/安静时段与通知预览控制，字段与可用范围等待后端冻结。

角色主题使用语义 Token 映射，角色色不能覆盖错误/警告语义或降低正文对比。应用导航、字体层级、间距与组件规则稳定；角色头像、强调色、壁纸、互动与桌宠按同一角色版本切换。全局字体缩放、高对比度、降低动态效果优先。资源缺失使用中性回退，不能保留旧角色主题或桌宠制造混合状态。

## 4. 模型设置结构

设置中的“模型”页采用用途优先的纵向布局，不把所有模型塞进一个无分组下拉框：

```text
模型
  聊天与看图    [聊天模型选择] [视觉模型选择/沿用现有可选语义]
  语音          [保留现有语音模型设置]
  记忆检索      Embedding 模型列表、用途说明、接入状态
  模型库        搜索、来源/用途筛选    [刷新本地模型] [添加自定义模型]
                名称、来源、能力、标签、可用状态、更多操作
  当前用途的参数设置（高级参数按需展开）
  保存更改 / 取消
```

### 4.1 数据来源与列表规则

- 所有条目读取 `GET /api/v1/models`，不硬编码新下载模型名称或数量；语音继续使用现有语音接口。
- 用 `id` 维持选择，用 `displayName` 显示名称；同名模型补充来源与 `modelName`，长名称可换行或展开查看。
- 用 `capabilities` 判断用途，用 `source` 判断来源和可编辑权限。标签只用于检索和展示，用户把标签改成 chat 不能赋予聊天能力。
- 来源显示为“内置”“本地”“网络”；兼容 `custom-local` 为旧本地配置，不套用网络编辑/删除操作。
- `available=false` 保留可见并标记“文件不可用”，禁用新选择，不静默替换已保存模型；提示恢复文件后刷新，不暴露后端真实路径。
- 聊天选择排除纯 Embedding 模型；视觉能力依据明确投影，不把 `vision-candidate` 标签当成已可用的视觉能力。
- 每行优先显示名称、用途和状态；自动标签折叠展示少量，更多可展开。`source=network` 才显示网络编辑/删除；标签编辑遵循后端限制。
- 本地刷新调用扫描接口，显示扫描中状态和返回的新增数量；失败保留原列表和未保存选择，成功根据稳定 ID 合并，不清空调参草稿。
- 文件可用、模型已选择、模型运行就绪为不同状态。不得把 `available=true` 或旧 `state=ready` 直接显示为“模型已加载”。

### 4.2 自定义模型

“添加自定义模型”打开页内编辑区，说明本次添加的是 OpenAI-compatible 服务。界面提供本地 GGUF 使用“刷新本地模型”的说明入口；不要求输入本地模型路径，不调用旧 custom 接口创建本地配置。

| 控件 | 字段与行为 |
|---|---|
| 显示名称 | `displayName`，持续显示 Label，不仅依赖占位文字 |
| 模型标识 | `modelName`，示例仅用于提示，不自动冒充真实模型 |
| 服务地址 | `baseUrl`，提示远程 HTTPS、回环可 HTTP；错误定位到字段 |
| 能力 | `capabilities`，聊天/视觉/Embedding 按当前 DTO 与服务端验证保存；声明能力不代表自动接入对应用途 |
| 上下文与生成参数 | `contextSize`、`maxOutputTokens`、`temperature`、`enableThinking`，高级分组按用途呈现，采用后端有效值和验证，不自行推导模型推荐值 |
| 标签 | `tags`，支持编辑与删除，展示服务端规范化结果 |
| 网络固定参数 | 当前请求中的 `computeDevice=remote`、`gpuLayers=0` 由适配层按契约填写，不把本地 GPU 设置暴露成网络必填项 |

当前认证来自环境变量，不在表单中新增无法保存的 API Key 输入框。可显示简短“认证由运行环境配置”说明；当前无冻结的连接测试接口，不添加虚假的“测试成功”按钮。

新增或编辑保存后使用后端返回对象刷新模型库，但不自动切换当前聊天模型。删除只对网络配置开放，确认明确“删除配置”；选中模型不能删除时保留原配置并提示先切换。取消编辑不发写请求。

模型库 CRUD/标签编辑为明确的独立保存动作；页面底部保存用于用途选择与参数。要标明其保存范围，避免用户以为关闭整个设置页能撤销已经保存的模型配置。

### 4.3 Embedding：必须分两阶段

已核对事实：后端可扫描并返回 Embedding 能力；当前 `UpdateModelSelectionRequest` 只有文字、视觉、语音选择与调参字段，没有 Embedding 选择字段。`MEM-004` 尚待开发；下载文件或直接推理测试通过不等于长期记忆已采用向量检索。

**现在可实现：** 在“记忆检索”分组展示 Embedding 列表、来源、可用性和用途说明：“Embedding 将文本转换为用于记忆检索的向量，不负责生成聊天回复。”提供模型库刷新入口，当前显示“已发现模型；长期记忆向量检索尚未接入”。不得显示可保存的选择器、“已启用”或假索引进度，也不得把 ID 写入聊天选择字段。

**等待 MEM-004 契约后：** 接入独立的选择、保存、运行/索引状态和恢复操作。后端需先明确选中 ID 的存储、无模型/禁用语义、切换模型后的索引处理、维度兼容、失败与回滚、进度投影及原子保存规则；前端只消费结果，不生成向量、启动进程或迁移索引。具备完整闭环后才能验收为“Embedding 可启用”。

## 5. 接口与实现依赖

下表按本次工作区的文档、Contracts 和 Client 核对，不能推断已进入发行包；前端开工时再次确认所用后端版本。

| 功能 | 当前接入点 | 状态 |
|---|---|---|
| 模型库 | `GetModelsAsync` / `GET /api/v1/models` | 可接入 |
| 本地刷新 | `ScanModelsAsync` / `POST /api/v1/models/scan` | 可接入 |
| 标签 | `UpdateModelTagsAsync` / `PUT /api/v1/models/{id}/tags` | 可接入 |

| 模型选择 | `PUT /api/v1/models/selection`；全设置保存用 `PUT /api/v1/settings` | 按现有全量及原子语义保留其他选择和调参 |
| 运行状态 | `GET /api/v1/runtime` | 使用 `modelState` 等分层状态，不自行启动模型 |
| 外观 | preferences、appearance 媒体及 settings 接口 | 复用现有字段；新增字段先冻结契约 |
| Embedding 列表 | `ModelProfileResponse.Capabilities.Embeddings` | 可展示，选用与记忆运行状态待 MEM-004 |
| 头像互动与预设编辑 | COMP-002/003 → COMP-004 | 草案，先冻结 API |
| 主动消息与通知 | COMP-005 → COMP-006 | 调度、未读/已读持久化及投影需明确后接入 |
| 角色主题与桌宠 | COMP-007、PET-002～008 | 角色体验投影与资源版本待实现 |

模型错误映射到字段或对应分组，保留草稿；全局错误提供重试。迟到刷新不能覆盖新选择。保存成功以最终服务端投影和 `runtimeAction` 为准，不由前端猜测重载行为。

## 6. 组件规范与响应式

优先复用现有语义 Token 和控件样式。以下尺寸使用 Avalonia DIP，为起始设计参数，实机缩放时按内容调整。

| 项目 | 规范 |
|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48；正文区域边距默认 24，窄窗 16 |
| 字体 | 中文清晰的系统 UI 字体；页标题 24/32，分组 18/26，正文 15/24，标签与辅助信息 13/20 |
| 阅读与表单宽度 | 消息列最大 760，设置表单最大 800；不将宽屏多余空间塞满卡片 |
| 头像与操作 | 主角色头像 48；图标按钮命中区至少 36×36，触控目标至少 44×44；交互含可访问名称 |
| 圆角 | 输入与按钮 8，局部阅读表面/面板 12，大型输入容器 16；避免任意新值 |
| 模型行 | 最小高 64，双行文本、标签和高 DPI 下可增高；更多操作保留键盘入口 |
| 互动面板 | 宽 240～320，按窗口可用空间调整位置，不越界 |
| 状态 | Default、Hover、Pressed、Focus、Disabled、Loading、Error、Selected 均覆盖；选择不能只靠色差 |
| 对比与色彩 | 正文/辅助文字目标至少 4.5:1，关键非文本控件及焦点目标至少 3:1；紫与黄色控制用量，黄色用于少量品牌识别 |

宽窗（工作区宽 ≥1100）历史可采用约 260 宽侧栏；窄窗（860～1099）历史改为可关闭抽屉，打开后正确管理焦点与 Esc，底层背景不跟随抽屉重裁切。模型筛选工具栏允许换行，网络模型表单改单列。

维持当前 860×620 最小桌面窗口可操作：角色名截断但有完整名称入口，输入区随内容增高有上限，设置内容独立滚动、保存区固定且不遮住最后字段。验证 100%/150%/200% DPI 与字体放大，不以单纯缩小整页应对。移动端尚无明确交付目标，不在本次额外建设独立移动应用。

## 7. 前端实施顺序与交付

1. 认领计划中 UI-021/022；检查后端 MODEL-008 对应接口与现有 Client，保留其他协作者改动。先提交结构线框或隔离预览供设计检查，再完成组件实现，不以换色代替布局修正。
2. UI-021：完成连续工作区背景、构图参数恢复、消息阅读表面、头像与角色切换入口分离。角色互动真实动作接入继续归 COMP-004，依赖 COMP-002/003。
3. UI-022：完成动态模型库、自定义网络模型、扫描与标签、用途选择及状态；同步交付 Embedding 只读结构。

## 9. 风险与完成口径

当前最高视觉风险是壁纸可读性与构图，最高接口风险是将“已存在的模型文件”误报为“记忆能力已接入”。单击/双击存在响应延迟与误触权衡，需实机验证；角色主题若直接覆盖原始颜色会破坏语义和对比，必须通过 Token 约束。

本文完成仅表示设计交接可供前端执行。UI-021、UI-022 及相关 COMP/MEM 任务应分别记录完成情况；未冻结接口的功能不能因预留了界面位置而标为已完成。发布、提交和任务派发不在本次文档交付动作内。
