## 1. 标定对象与非目标

### 1.1 要标定的旋钮

| 旋钮 | 现值 | 出处 | 备注 |
|---|---|---|---|
| 关键词重合门 | `0.25` | `MemoryQueryService.cs:48` | 当前生产唯一实际生效的相关性门 |
| 余弦相似门 | `0.65` | 同上 | F1/F2：上线前置门 |
| 总分地板 | `0.35` | `:57` | 见 §1.3：与 recency 强耦合，可能不是独立旋钮 |
| 半衰期 | event `14d` / preference `365d` / 其他 `90d` | `:50` | 只经 recency 项进入，占 0.10 权重 |
| 注入条数上限 | `min(6, MaxMemories)` | `:64` | 与预算共同决定"少而准"的"少" |
| 置信下限 | `0.5` | `:22` | 现值使抽取（.9）与人工（1）都通过，等价于不筛选；要不要收紧是标定问题 |

不动的权重（`0.35/0.20/0.10/0.15/0.10/0.05/0.05`，`:55-56`）：一次只改一组旋钮。七维权重同时网格会把人淹死，且不可归因。

### 1.2 非目标

- **不**为召回率牺牲误召回。`PROJECT_PLAN.md` §5.5 与 `docs/eval/README.md:214` 把"误召回"排在新增功能之前；本协议的约束方向是单向的（见 §8）。
- **不**产出"经过用户验证的阈值"。本轮是**工程标定**：语料合成、标注者项目内、样本量小。写结论时必须带这个限定，不得对外宣称已用户验证。
- **不**重新定义 Useful / False / Missing Recall。口径以 `docs/eval/README.md` 第 66–72 行"Memory 三项统计"为准，本文只**沿用并向下拆分**。
- **不**修改 `docs/eval/scenarios.json`（QA 所有的未跟踪文件）。§9 只是提案。
- **不**碰 Knowledge Graph、rerank 模型、查询改写。1.0 不做（契约 §1 非目标）。

### 1.3 一个必须先摊开的问题：`0.35` 地板现在几乎不起作用

地板项是可解析计算的。抽取记忆的相关性之外贡献为
`0.15·importance(.6) + 0.05·confidence(.9) = 0.135`，再加 `0.10·recency`；相关性贡献为 `0.35·max(k,s) + 0.20·k`，纯关键词时即 `0.55k`。
过地板需要 `0.55k ≥ 0.215 − 0.10·recency`。于是：

| recency | 刚过 `0.25` 门的记忆能否过地板 | 地板反推的等效关键词门 |
|---|---|---|
| 1.0（刚写入） | 能（`k ≥ 0.209` < `0.25`） | **地板无效**，只有 `0.25` 门在筛 |
| 0.775 | 临界 | `k = 0.25`（两门重合） |
| 0.5 | 不能 | `k ≥ 0.300` |
| 0.1 | 不能 | `k ≥ 0.373` |
| 0（极旧） | 不能 | `k ≥ 0.391` |

结论：**"总分地板"实际是一个随记忆年龄自动抬高的关键词门**。临界年龄（按半衰期）为 event ≈ 5.1 天、其他 ≈ 32.9 天、preference ≈ 133 天。

这不是 bug——"旧事需要更强匹配才配注入"是一个合理的**产品立场**。但它是**偶然继承来的**，不是设计出来的。本协议要求标定结束时对此给出显式裁定（§8 R3）：要么承认年龄耦合并按年龄分层报告，要么把地板改成纯相关性判据（例如把 `0.35·max(k,s)` 单独设门、把 popularity/recency 项从地板里移除）。**不要在没搞清这点之前去网格搜 `0.35`**——那只会搜出 recency 的镜像。

## 2. 方法论主干：两阶段分离，再加三段归因

F3 决定了：端到端指标里"漏召回"绝大部分来自抽取拒收。若直接拿端到端 U/F/M 去调 `0.25`，就是把正则的词表问题算到检索头上。所以：

### 2.1 阶段 R（检索隔离，确定性，不用模型）

绕过抽取器，直接用仓储写入口（`SaveManualAsync` / `SqliteMemoryRepository` 落库路径，`SqliteMemoryRepository.cs:203-243`）把 **gold 记忆**灌进库，再调 `MemoryQueryService.RetrieveAsync`，oracle 就是 `MemoryContext.Hits` 与 `RetrievalTrace`（`considered / relevant / selected`，`MemoryContracts.cs:70`）。

- 无模型、无 UI、无时钟漂移，可放进 `Pry.Core.Tests` 长期跑；这就是为什么它能当回归护栏。
- 阈值只在这一阶段调。
- `Trace.Reasons` 里的 `keyword/x semantic/x recency/x ...`（`MemoryQueryService.cs:58-59`）是逐条判因的现成证据，不要另造埋点。

### 2.2 阶段 G（生成与端到端，用真实模型，QA 跑）

完全沿用 `docs/eval/README.md` 第 68–70 行的 `expectedFactIds` / `usefulFactIds` / `falseClaims` 标注法与 U/F/M 计数，精确率 `U/(U+F)`、覆盖率 `U/(U+M)`、含错误召回查询占比，分母为 0 记 N/A。

阶段 G **不用于选阈值**，只用于回答"检索到的东西模型是否真的用对了"。README:68 已明确"仅检索到、没有实际使用的不算 Useful"。

### 2.3 Missing 必须拆成三个来源

阶段 G 报出的一条 Missing，标注者必须再归入其一（这是本协议对 QA 模板的唯一新增字段）：

| 归因 | 判据 | 责任面 |
|---|---|---|
| **M-extract** | 该事实在库里根本不存在：源消息未过 `ExplicitFactExtractor`（`MemoryWriteback.cs:14,19`） | MEM 抽取词表。**与阈值无关，不要去调 `0.25`** |
| **M-retrieve** | 库里有，但阶段 R 复现同查询时未进 `Hits`：被 `0.25`/`0.35` 门、topic 去冗或注入上限挡掉 | 本文标定对象 |
| **M-generate** | 已进 System Prompt（在预算内且未进 `Dropped`），模型输出没体现 | Context 渲染或提示侧。另案 |

不允许出现"归因未知的 Missing"。这条拆开之后，M-extract 占比就是**该阶段阈值调优的收益上界**——如果一轮里 80% 的 Missing 是 M-extract，那么 §6 的整个网格可以直接缩范围。

## 3. 语料设计

四个集合。全部**合成**，中文为主。`AGENTS.md` 规则 6 与 `docs/eval/README.md:54` 禁止真实用户聊天入库；因此语料本身若需版本化，只能是合成脚本，且必须显式标记为合成数据。建议放在被跟踪的测试数据目录（例如 `tests/Pry.Core.Tests/Data/memory-calibration/`），由 QA Owner 定夺位置。

### 集 A · 生态集（测有用召回）
贴近本产品的真实话题域：后摇/音乐口味、饮品与食物偏好、作息与时区、居住地、名字与称呼、工作性质、追番与游戏、宠物、身体限制、送礼与纪念日。每条查询配 `expectedFactIds`，并保留"同主题多事实"与"事实随时间更正"的样本。
规模建议 60～80 条查询，正常话题:更正话题 ≈ 3:1。

### 集 B · 对抗近失集（本协议最重要的集，测误召回）
针对 §0 的结构性风险专门构造，每条都标 `expectedFactIds = ∅` 或只有 1 条：

| 代号 | 攻击面 | 构造要点 | 对应事实 |
|---|---|---|---|
| B1 | `min` 归一短记忆 | 记忆归一化后只剩 1～2 个二元组（如名字类短事实），查询只偶然重合 | F4 |
| B2 | 跨词切分假重合 | 二元组跨越词边界而偶然相同（"用户喜欢"切出 `户喜`，"户喜"可被另一句"那户喜欢…"撞上） | F5 |
| B3 | 停用表边界 | 查询词全部落在 17 项 `Stop` 里（如只问"喜欢什么"）→ `terms.Count=0` → `keyword` 被置 0（`:43`）。确认此路径**不会**反向把整表记忆放行；同时确认该查询**必然空召回**这一后果是否可接受——短问句被停用表吃光是漏召回的结构性来源，不是阈值问题 | F5 |
| B4 | 同主题不同事实 | 库里"喜欢红茶"，问"喜欢什么咖啡"：主题相近、事实不同 | §6.2 topic 去冗 |
| B5 | 中英混排与大小写 | `Terms` 走 `ToLowerInvariant`，验证大小写与全半角不误伤也不漏放 | F5 |
| B6 | 已删/已 superseded/跨作用域 | 必须来自 §7 的墓碑与更正态，不得进 `Hits` | 契约 §7.2 |
| B7 | 语义越界（仅在语义臂开启时） | 同一话题但不同事实，检验 `0.65` 是否放行 | F1/F2 |

规模建议 40～50 条，B1/B2 各不少于 10 条（它们是 F4/F5 的直接探针）。

### 集 C · 无关查询集（测沉默率）
纯技术问答、纯任务指令、与任何已存记忆都不相干的闲聊，且库内有若干**语义相邻但应当沉默**的记忆。用来量 §5.2 的"无关时沉默率"。规模 30 条。

### 集 D · 抽取词表集（阶段 G 用，不入检索网格）
覆盖四动词的正/负/边界：第三人称转述、引号内、假设句、"如果/比如"、带附件、>100 字、更正句式、以及**应记但未覆盖的表达**（"我一般喝美式"、"我不吃香菜"、"我在成都"——注意"住在"与"在"不同）。它的答案是 M-extract 的分布，也是后续是否扩词表的依据。规模 30 条。

### 分层与切分
- 切分：dev 60% / holdout 40%，**按集合分层随机切**，切分一旦定下不得移动。网格只在 dev 上跑；holdout 只跑最终候选。**如果 holdout 明显差于 dev，结论是"阈值被拟合到语料上了"，而不是"再调一版"**。
- 分层报告维度（沿用 README:70 的分组要求，再加两条）：本地/API、关系阶段、正常/降级、相关/无关、`origin`（extraction / manual / correction）、pool size（见 §5.3）。
- **统计力度的诚实声明**：单臂 40 条时，两条曲线相差 10 个百分点以内基本是噪声。本协议只求"方向 + 数量级"与可回归的下界，**不要**发布带 2 位小数的精确率排名。样本量决定结论形态，不要反过来迁就结论。

## 4. 标注协议

1. **查询时标注（事前）**：写语料时就填 `expectedFactIds`，不得事后按检索结果补。与 README:68 一致。
2. **事后标注**：`usefulFactIds` / `falseClaims` + 原因，由人工按证据判，模型不得自证命中。
3. **双标 + 一致性**：集 B、C 全部、集 A 抽样 30% 由两人独立标；报告 Cohen's κ。κ < 0.6 的分类视为**判据没写清**，回去修 rubric，不要靠仲裁把数字做上去。仲裁只做追加，不覆盖原始双标记录。
4. **判据要能被反驳**：每条 `falseClaim` 必须写属于哪一类（虚构 / 过期 / 已删 / 跨作用域 / 不相关却硬插入），对齐 README:68 的定义。"感觉怪"不算原因。
5. 原始脱敏标注记录必须保留（README:72：不能只发综合分数）。

## 5. 指标

### 5.1 阶段 R（检索层）
| 指标 | 定义 |
|---|---|
| 注入准确率 | `Hits ⊆ expectedFactIds` 的比例（不是@k，是"注入进去的东西里对的比例"），集 A + 集 B |
| 检索召回率 | 阶段 R 里 `expectedFactIds` 进入 `Hits` 的比例（此时**不含**生成，别和 README 的覆盖率混用同名） |
| **无关时沉默率** | 集 B/C 中 `Hits` 为空的比例。**这是本标定的一等指标**：误召回的真实代价就是"角色硬插一句不相干的旧事" |
| 门构成 | 通过样本里各信号占比：仅靠 `keyword`、仅靠 `semantic`、两者都靠。用来发现某一门是否独大 |
| 年龄耦合曲线 | 按 `age/halfLife` 分桶的等效关键词门，验证 §1.3 的推导在实测中成立 |

### 5.2 阶段 G（生成层）
照抄 README:70：`U`、`F`、`M`；精确率 `U/(U+F)`、覆盖率 `U/(U+M)`、含错误召回查询占比；每组同时报告分母；分母 0 → N/A，未跑 → NotRun，不写 100%。`5F+M` 只作**诊断**，且只在阶段 G 内使用——它跨阶段没有意义（§2）。

### 5.3 两个必须显式处理的混淆
- **预算遮蔽**：`:64` 条数上限与 `:67` 字节成本先于阈值决定最终注入。集内 pool 大小不一致会让"召回低"其实是"被裁掉"。做法：**按 pool size 分桶**，并在 dev 网格的一臂里把预算放到远大于必要值（只做离线实验，不改生产默认），把"门挡掉"和"预算裁掉"分开数。
- **估算器偏保守**：F6 使真实分词下能塞进的条数约为现在的 2～3 倍。任何在字节估算下调出的阈值，接到真分词器上都会变松。控制臂见 §7。

### 5.4 硬门槛（不接受平均分抵消）
README:72：**跨用户/实例泄漏、删除复活 → 直接 Critical 阻塞**。标定过程中只要出现一例可复现，就停止调参、先修不变量。

## 6. 网格扫描设计

只扫 §1.1 的旋钮，一次一组，其余冻结：

1. **G1 关键词门**：`0.15 / 0.20 / 0.25 / 0.30 / 0.35 / 0.40 / 0.45`。这是当前唯一生效门（F1），主扫描。
2. **G2 地板**：**不要盲扫**。先按 §1.3 把地板改写成"等效关键词门 vs recency"曲线，再决定它是保留（承认年龄耦合）还是替换为纯相关性判据。扫之前必须先做这个替换实验。
3. **G3 半衰期**：event `7/14/30d`、默认 `60/90/180d`、preference `180/365/∞`。注意半衰期只通过 `0.10` 权重起作用，单独扫它大概率被 §1.3 的地板耦合吞掉。
4. **G4 注入上限**：`3 / 4 / 6`（含与预算的联合臂）。
5. **G5 置信下限**：`0.5 / 0.7 / 0.85`。现值 `.5` 不筛任何来源，抬到 `.7` 起效的对象其实是**低置信抽取**（`.9` 仍过），实际是在测"抽取记忆是否该比人工记忆更难注入"。
6. **G6（延后）语义门** `0.55 / 0.60 / 0.65 / 0.70 / 0.75`：**前置条件是 F1/F2 修复**（`ContextBuilder.cs:35` 传入真实 `semantic`）。且必须**按 embedding 模型分别标定**——余弦分布是模型属性，换模型即作废。标定时记录模型 id + 权重 hash，写进运行记录与 trace。

每臂产出：集 A/B/C 三项 §5.1 指标 + 门构成 + 按 pool size 分桶。全部跑 dev；候选（≤3 个）跑 holdout。

## 7. 分词控制臂（防止把分词缺陷固化成常量）

同一套 dev 语料、同一网格，跑两臂：
- **T0**：现状 `Terms()`（字符二元组）。
- **T1**：真实中文切分（词典或分词器）+ 同一 `min` 归一，**只换切分**，不改归一。
- （可选 T2）：换切分 + 换归一（`overlap/|terms|`，即查询侧归一），**同时**验证 F4。

判定：
- 若 T1 的最佳门与 T0 相差 > 1 档（例如 0.25 vs 0.35），说明**阈值数值主要是分词器属性**。此时不得把 T0 的数值冻结进生产常量；应先落 T1 的切分改动，再重新标定，或显式在代码注释与契约里写"本常量仅对当前分词器有效"。
- 若 B1 子集在 T0 的误注入率显著高于其他子集，说明 F4 的 `min` 归一是主因，**改归一优先于调阈值**——调阈值只是给一个结构性缺陷加补丁。
- 预算维度同理：接真分词器后必须重跑 §5.3 的预算臂。

### 7.1 语义通道的上线前置门（建议，需 Owner 裁定）
在 §6 G6 与 §7 完成之前，**embedding 适配器不要以默认开启方式接线**。建议：接线时默认关闭 / 显式配置开启，且 `DegradedKeywordOnly` 与 `Unavailable` 必须继续按契约 §6.4 可区分（QA-005 提的静默回落问题正是这一路的教训：静默把"最不离谱的一条"当"相关"，就是误召回的主要成因）。

## 8. 选择规则（写死，避免事后合理化）

按顺序应用：
1. **不违反 §5.4 硬门槛**。
2. **无关时沉默率（集 C）≥ 下限 `S`**。`S` 是产品决策，不是工程结论。本文给出建议默认 **`S = 0.95`**（每 20 条纯无关查询最多 1 条被注入），**待 Owner 批准或改写**。
3. 在满足 2 的候选里，取**注入准确率（集 A + 集 B）**最高者。
4. 打平时取**注入条数更少**者（契约 §6.2 "宁少勿滥"）。
5. 只有走到这一步才允许用 `5F+M` 做诊断性复核；它不得作为目标函数。
6. holdout 上重报 2、3，并**同时报 dev 与 holdout 两列**。

产出必须是三行以内可复述的结论：`{关键词门, 地板处置, 注入上限}` + 各自指标 + 未覆盖风险。

### 8.1 标定可能要改代码，不只是改数字
若 §7 判 T0 数值不可固化，或 §1.3 判地板应改成纯相关性判据，那结论是**代码改动**（`MemoryQueryService.cs:43,48,57`），需回到 MEM-005 的实现 Owner。本协议不授权我或 QA 直接改检索器。
