## 3. 方法论主干：两阶段分离，再加四段归因

### 3.1 阶段 R（重放，确定性，不用模型）

把语料的 `(时间戳, 文本, 附件/提及标志)` 灌进真实 `ConversationRuntime` + 真实 `MemoryDatabase`，用固定 `TimeProvider` 重放，oracle 是 **trace 帧序列 + `messages` 行**。

- 无模型、无 UI、无时钟漂移 ⇒ 可长期跑，这就是回归护栏；**阈值只在这一阶段调**。
- 与假时钟单测的区别必须先说清：假时钟单测证的是"代码按常数行动"，标定量的是"常数是否匹配真实节奏"。所以阶段 R 的输入必须来自**真实节奏的采样**（§4），不能是 QA 手写的整数间隔——否则 F5 那条限制就被绕成了自证。
- 现成证据面优先，不另造埋点：`Gate trigger:<Disposition>`（`ConversationRuntime.cs:651`）、`Buffer consumed_silently`（`:664`）、`runtime-state` 的 `pendingInputCount`/`recentTurns`、`replyFrequency`/`triggerMode`/`isGroupChat` 三个投影。

### 3.2 阶段 G（真实模型与端到端，QA 跑）

真实模型只提供"轮开起来之后她说什么"。阶段 G **不用于选阈值**，只回答两件事：误开轮的代价（她插了一句不相干的话）、漏开轮的代价（她该接没接）。运行必须固定：角色卡 hash、Provider 与模型名（**只记名，不记密钥**）、seed、档位、语料版本——与 `docs/eval/run-template.md` 的"工程与模型分开归因"同源。

### 3.3 每条"没回／回错"必须拆成四类归因之一

| 归因 | 判据 | 责任面 |
|---|---|---|
| **M-mode** | 这次判定根本没走被标的门（默认 `MessageCount` ⇒ 必要性箱的每一条都是 M-mode，F1） | 模式与发行立场，作者裁定面。**与阈值无关，不许拿它去调 70 分** |
| **M-gate** | 走了门、被某个常数挡住或放行（窗、节奏、计数阈值、退避） | 本文标定对象 |
| **M-port** | 宿主根本没给这个判定提供输入（focus、群聊、真实 advisor） | 接线 Owner。标 `Blocked` + 归属，**不许记 Pass**（同 `memory-recall-calibration` §9 对 MEM-007 的处理） |
| **M-content** | 轮开了、内容不合期待（含信封/内部草稿泄漏） | Character Intelligence（`DEF-P1WALK-01` 一族）。**不得折算进触发层阈值** |

**不允许出现归因未知的样本。** 拆开之后，M-mode 与 M-port 的占比就是"本轮阈值调优的收益上界"——若某类里 80% 是 M-port，那一臂直接收缩范围。

## 4. 语料与期待标注

1. **五类节奏必备**：连续短发、单向陈述（无提问词）、明确提问、征询/征求意见、长时间空窗后回来继续说。真实模型与真实使用记录在作者本机（QA 不读密钥、不代填、不入库），QA 侧只取**时间戳、文本、期待标注**三列。
2. **集合形状**（沿用 `memory-recall-calibration` §3 的四集设计，替换攻击面）：
   - **集 A · 该成轮**：五类里的提问/征询/连发，每条带期待"开口"。规模 ≥40 段、每段 ≥8 条用户消息。
   - **集 B · 不该成轮（本协议最重要的集）**：自言自语、纯短反应、连续碎句被过度合并、隔得过久仍被并成一轮。每条期待"沉默"。规模 ≥30 段。**误开轮的代价高于漏开轮**（用户在等答复 vs 用户没指望答复），所以 B 的权重方向是单向的。
   - **集 C · 空窗与自醒**：长时间无输入后攒够的部分消息，量"到点自己醒"（`TIM-009` 已有自动化锚点）与退避不可达（F4）的实际后果。规模 ≥15 段。
3. **期待标注必须独立于模型**：写语料时就填期待（事前标注），不得按检索/运行结果补。集 B、C 全量 + 集 A 抽样 30% **两人独立标**，报告 Cohen's κ；**κ < 0.6 判为"rubric 没写清"，回去修判据，不许靠仲裁把数字做上去**；仲裁只追加、不覆盖原始双标记录。rubric 里放 2 个已知正例 2 个已知反例做校准检查。
4. **切分**：dev 60% / holdout 40%，按集合分层随机切，**切分定下不得移动**；网格只在 dev 上跑，候选（≤3 组）跑 holdout 并**两列并报**。holdout 明显差于 dev ⇒ 结论是"值被拟合到语料上了"，不是"再调一版"。
5. **统计力度的诚实声明**：单臂 30～40 段时，两条曲线相差 10 个百分点以内基本是噪声。本协议只求**方向 + 数量级 + 可回归的下界**，不发布带两位小数的精确率排名。**样本量决定结论形态，不要反过来迁就结论。**
6. 原文语料与标注**不得提交**（`AGENTS.md` 第 6 条：用户导入内容不得入库；`docs/eval/walkthroughs/` 已在 `.gitignore`）。若需版本化，只能版本化**合成脚本**并显式标注为合成数据，位置由 QA Owner 定。仓库里只留统计与判据，不留原文。

## 5. 指标与硬门槛

| 指标 | 定义 | 阶段 |
|---|---|---|
| 误开轮率 | 集 B 中实际开了轮（trace 有 `Gate trigger:Run` 或产生 assistant 行）的占比 | R / G |
| 漏开轮率 | 集 A 中期待开口而实际沉默的占比 | R / G |
| 合并率 / 误合并率 | 集 A 连发被并成一轮的比例 ／ 间隔超过 `MaxBufferMs` 设计意图仍被并的比例 | R |
| 自醒正确率 | 集 C 中"没有新输入但到点成轮"的比例（`idle_compensation` 分支，`TurnScheduler.cs:161`） | R |
| 节奏分布 | 逐会话 inter-arrival 的 P50/P95，与 `Window`/`BurstFloor`/`MinimumAverage` 的关系 | R |
| 端到端延迟 | 首气泡与整轮耗时 P50/P95（trace `At` 差 + DB 时间戳） | G |

**硬门槛（不接受平均分抵消，出现一例可复现即停止调参、先修不变量）**：

1. 消息丢失或重复投递——契约 §3.10 那条底线（"静默不等于丢消息"）；
2. 切会话／换房间后串状态（§8 第 3 条第四行为）；
3. 旧流改新房间的界面（`PLT-013` 的代次门控）；
4. 用伪造生产者（假 `IsGroupChat`、假 focus）把不可达标成可达（§8.2）。

## 6. 逐组判据与网格

**一次只调一组，其余冻结**（同 `memory-recall-calibration` §6）。`目标值` 一列此刻**故意留空**：那是作者与 Owner 在采纳本文时要写死的产品意图，QA 不代拍；**留空即表示该组此刻不具备可判的通过条件**。

| 组 | 量什么 | 通过条件（先立后跑，跑完不得回改） | 网格 | 不通过时 |

## 7. 选择规则（写死，避免事后合理化）

按顺序应用：

1. 不违反 §5 的四条硬门槛；
2. **误开轮率 ≤ 上限**（集 B）——方向单向：宁可不说话，不可插错话；
3. 在满足 2 的候选里取**漏开轮率最低**（集 A）；
4. 打平时取**开轮更少**者（沉默代价低于误插话；这条是产品立场，**待作者批准或改写**，同 `memory-recall-calibration` §8 对 `S` 的处理）；
5. 只有走到这一步才允许用阶段 G 的主观评分做诊断性复核，它**不得作为目标函数**；
6. holdout 重报 2、3 两列。

产出必须是三行以内可复述的结论：`{窗, 节奏, 计数阈值/必要性阈值}` + 各自指标 + 未覆盖风险 + 归因分布（M-mode/M-port 占比即收益上界）。

## 8. 出口只有三种（每个参数各归一种，不许第四种）

1. **保留并记录裁决**——量级经标定证明可用，契约 §5 处置列与 §5.1 写明"经 2026-MM-DD 标定保留"；
2. **以标定值替换**——改 Pry 默认，同步契约 §5、发行说明与该参数的测试锚点；
3. **显式声明 1.0 不启用该机制**——写清受影响判据与 DEV 行，转 `NotApplicable` 并**保留编号**。

**§8 第 2 条只有在 §6 表里每一行都归入上述一种、且逐条有台账之后才成立。** 判定权分布：逐值裁决＝作者；判据与读数＝QA；契约 §5/§5.1/§6/§9 文本＝RT-002 Owner；阶段指针＝作者/守门人。任何一方不得替另一方落笔。

**标定可能要改代码，不只是改数字**：若结论要求让评分细节可见（F6）或补只读投影（F5），那是 Owner 的一刀，本文不授权 QA 直接改 Runtime；同理，若结论要求真实 `IReplyAdvisor` 才谈得上评必要性（F2），前置在 Character Intelligence，不在标定轮内。

## 11. 未决与风险

- 合成语料不代表真实用户分布；本文档住"机制正确 + 方向"，不代表产品验收。真实分布要纵向观察补（`docs/eval/longitudinal/`）。
- 阶段 R 绕过真实模型，因此**不能证明"她说了合适的话"**，只证明"门在不在预期点开合"。
- 双标两人同属一个项目，κ 高也可能共享同一套偏见；缓解只有 §4 的校准例，无法根治。
- F1/F2 的合取意味着最坏的执行偏差是**先切默认后标定**——那会把未标定的 70 分门与一个恒真的 advisor 一起带进生产，且界面上看不出问题。本文 §2 非目标与契约 §5.1 是同一条闸门的两种写法。
- 若作者最终选"1.0 不提供频率旋钮"，则 §6 的 `ReplyFrequency` 行落为出口 3，本轮标定对 1.0 的净收益仅剩"给未来阶段留一套可复跑的判据"。这一点在采纳前必须说清，否则工作量与目标不匹配。
