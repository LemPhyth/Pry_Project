## 2. 两条语义修订（改了什么、为什么这样改）

**`PLT-007` 半开连接有界检出**（作者裁的那条）：`initialState` 由单档变两档——"服务端建立事件流后既不发也不关" ／ "**订阅连响应头都不作答**"。`expectedDecision` 明写两档**各用自己的时钟**（已建立的那条走"两个心跳周期 + 抖动余量"，起头那条走本机逐请求预算并交给上层退避）；`expectedOutputConstraints` 补"起头阶段的预算不得跟着 `HttpClient` 的兜底一起放宽"；`forbiddenOutcome` 补"把兜底那一档当作起头上限，于是一次无人应答的订阅把界面钉在四分多钟"。映射 5 → 6，新增 `Pry.Client.Tests.BackendRequestBudgetTests.An_event_subscription_that_never_gets_headers_fails_on_the_local_budget`。

**一条我自己给自己留的警告**：把两档机制并到一条永久 ID 下，代价是以后读 `PLT-007` 的人可能以为"心跳窗口"也管起头。所以 `expectedDecision` 里那句"两档各用自己的时钟"不是修辞，是这条合并唯一的防坏条款——**删它之前先删这条合并**。

**`REC-001` Model timeout / malformed response**（QA 自承接的那条）：`initialState` 补"客户端按请求分档配预算（转写那一档比共享档宽），`HttpClient` 兜底在最外一层"；`expectedDecision` 补"宽档请求在自己的那一档里跑完，不被共享兜底顶掉"；`expectedOutputConstraints` 补"兜底必须严格宽于最宽的逐请求预算（否则声明的那档永远轮不到做主），且每一档都是正数——负数在 .NET 里是‘永不超时’而不是‘超时很长’"。映射 7 → 8，新增 `…Transcription_gets_its_own_budget_without_loosening_the_shared_one`。选 `REC-001` 作邻条的理由是它已经拿着同文件的 `An_exhausted_whole_request_budget_reports_a_timeout_instead_of_a_cancellation` 与 `Timeout_reads_as_slow_not_as_an_error_code`，判的都是"有界失败＋错误语义可区分"。

**升版本口径**：本 README 写着"映射追加不升版本，语义修订才升"，本轮改的是四条字段文本 ⇒ `suiteVersion` 1.3.0 → **1.3.1**（不铸新号，`PLT` 极大值仍 14，脚本内的永久 ID 最小值表不需动）。
