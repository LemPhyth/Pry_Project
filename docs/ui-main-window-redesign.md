# Pry 主窗口重设计 / UI-019

日期：2026-09-12。实现分支：`codex/ui-main-window-redesign`。

本次以一套新的陪伴空间替代桌面启动时的双布局选择。原 `MainWindow` 保留在源码中；桌面入口统一创建重设计后的主窗口。既有 `messenger`、`card` 偏好继续保留，不迁移或覆盖用户数据。

## 当前问题

作者提供的五张截图暴露了结构问题：卡片窗口的浮动区域与正文互相挤压；Messenger 把导航轨道、会话列表和消息并列为常驻重心；背景图穿透所有功能区；角色编辑缺少稳定标签，保存操作可能被长表单推出视口。

先前对旧布局的配色、间距整理不足以解决这些问题，因此本次最终实现采用新结构，不继续将两版分别作为设计目标。

## 设计目标与结构

1. 顶部全局导航：品牌、陪伴、角色、记忆、设置和系统窗口控制。用户始终知道当前工作区。
2. 对话上下文：历史入口、当前角色与会话标题、开启新对话。点击角色入口可选择角色并开始新对话。
3. 阅读区：默认居中；助手使用头像与连续正文，用户使用低饱和底色区分发言。不为每段助手文字套卡片。
4. 输入区：与阅读列同宽，独立于滚动内容；回复状态、输入、附件/表情/语音与发送在同一区域。
5. 历史对话：默认收起，按需展开 260 DIP 侧栏；保留搜索、右键菜单与会话切换。
6. 角色、记忆、设置：替换整个下方工作区；顶部导航和返回对话入口始终可达。角色编辑的保存、保存并使用、完成、删除固定在底部，正文单独滚动。

这将常驻注意力集中在当前角色与正在进行的交流上，同时保留管理功能的明确入口。没有引入虚构亲密度、未经后端支持的角色状态或示例业务数据。

## 可执行视觉规范

| 项目 | 参数与行为 |
|---|---|
| 默认窗口 / 最小窗口 | 1180×800 / 860×620 DIP |
| 全局导航 | 高 64，文字导航；当前项有低饱和选中底色 |
| 阅读与输入列 | 最大宽 760，左右边距 32；助手正文最大宽 700，用户消息最大宽 560 |
| 角色身份 | 48 DIP 圆形头像；22 DIP 名称；长名称省略显示，点击区限制可用宽度 |
| 对话正文 | 15 DIP，行高 24；元信息 12 DIP；消息间距 24 |
| 输入区 | 最大输入高度 150；容器圆角 16；发送按钮高 36 |
| 品牌关系 | 紫灰中性表面、紫色操作；黄色保留于 Logo；无重复星形铺底 |
| 主题资源 | `PryVisualTheme` 统一管理；XAML 动态资源与代码创建的页面共用可更新画刷 |
| 按钮状态 | 主操作 Default / Hover / Pressed 持续保持文字对比；Focus 可见；Disabled 降低透明度 |
| 背景 | 限聊天阅读区。浅色遮罩至少 0.90，深色至少 0.84；关闭增强氛围时 0.96 |

沿用用户已有强调色。文档与预览中的淡紫按钮是候选品牌色示例，不表示静默改写已有主题。按钮文字依据实际强调色选择高对比前景；背景图不能穿透导航、角色工作区和表单。

## 状态与响应式

- 空状态说明可以开始交流；不把品牌图当作整页水印。
- 启动状态保留进度与说明；服务不可用在状态区域说明，并指向设置。
- 流式回复、取消、语音录入、上传附件、消息菜单等沿用现有客户端链路。
- 历史关闭后释放阅读宽度；切换角色/设置工作区不重建输入控件，保留未发送草稿。
- 最小窗口保留导航字号、输入按钮和点击区域；长消息滚动，角色名省略，不按比例缩小整个页面。
- 移动端不在本次 Windows 桌面实现范围。

## 验证与局限

使用真实 Avalonia 控件和渲染器，在隔离后端与本机临时预览程序中检查浅深主题、默认/紧凑窗口、历史展开、长名称、混排长消息、角色工作区及空状态。预览对话为内存测试内容，不写入用户日常聊天库。程序化检查历史可收起、工作区可打开和返回后草稿保留。

新增对比回归测试：采样 RGB 色域的自定义强调色，检查主按钮默认/悬停/按下；以纯黑/纯白作为最不利背景检查元信息对比。

Windows 截图工具曾完成一次早期界面捕获；重启后的两次捕获均报 `foreground window did not report a process id`。最终预览来自 Avalonia 渲染器，不宣称是原生窗口截图。尚未完成 150% / 200% 系统 DPI、实际鼠标焦点与录音设备的人工验收；这些不由渲染图或单元测试代替。

## 风险与回滚

本次改变默认导航位置与历史展示方式，原有用户需要重新熟悉入口。旧窗口选择不再出现在设置中；旧偏好仍按原格式读写。

回滚应仅撤销本次前端与文档差异，不改用户数据、模型配置或历史消息。未增加 API、数据库迁移、第三方依赖或新的发行素材。
