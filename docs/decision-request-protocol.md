# Product Owner 裁决请求协议

> 适用范围：Pry 项目内**所有** Agent（守门人 / QA / 各层 Owner / Codex 分支）。作者 2026-09-24 明确要求本文件对当时全部在制的 Agent 生效，并且约束后续每一轮派活。

## 1. 为什么存在这条规则

项目处于多 Agent 快速开发阶段，作者**无暇审计整个项目的代码**。因此"内部编号 + 技术术语"形式的提问对他无效：他无法从 `DEF-P2TRIGGER-01` 这八个字推出自己正在决定什么，只能先去读台账——那等于把审计成本退回给他。

作者原话（2026-09-24）：

> 凡请求 Product Owner 裁决，不得只给内部编号或技术术语。必须同时给出：当前行为、用户可见后果、项目影响、推荐方案 …… 这个我才完全有能力决定。

结论：**提问的形态本身就是交付质量的一部分。** 一条按本协议写不出"用户可见后果"的请求，说明请求人自己还没有把它判清，应当先补判断再提问，而不是先提问再理解。

## 2. 四个必备部分（缺一不可）

| 部分 | 必须回答的问题 | 反例（不合格写法） |
|---|---|---|
| **当前行为** | 今天产品/流程**实际**怎么做，用使用者视角的语言描述，不用内部符号 | "`TurnGates` 的 `ReplyFrequency` 未标定" |
| **用户可见后果** | 维持现状，用户会看到什么、感知到什么变化；这条决定裁决的产品权重 | "会影响参数有效性判定" |
| **项目影响** | 阻塞/不阻塞哪条线、代价、可逆性、拖延的后果（含 Release 层面的硬约束） | "会挡住 §8 第 1 条" |
| **推荐方案** | 明确给出选项、推荐哪一项、为什么；不允许只列选项不推荐 | "请裁定 A/B" |

内部编号（`DEF-*` / `QA-*` / `PLT-*` / 阶段号 / commit SHA）**只能作为附注**出现在四个部分之后，用于让作者能查到台账，不能作为句子的主语。

## 3. 模板

```text
【待你裁决】<一句话说明这是产品决策还是流程决策>

当前行为：<今天实际发生什么>
用户可见后果：<用户看到什么、感知到什么；或明确说"看不到任何变化，但…">
项目影响：<阻塞什么、不阻塞什么、代价、是否可逆、不决定的后果>

A. <选项>：<立刻得到什么、付出什么、以后能不能改>
B. <选项>：<立刻得到什么、付出什么、以后能不能改>

推荐 <A|B>。<两三行理由，落在用户的利益和可逆性上，不落在内部整洁度上>
请裁决 A/B。<编号仅作附注：DEF-XXXX-NNN，Owner=…>
```

选项必须写成"立刻得到什么 / 付出什么 / 是否可逆"三件套，作者的选择成本才低于阅读成本。两个选项都写"推荐"等于没推荐。

## 4. 正例（作者给出的形状，逐字保留结构）

不合格写法：

> `DEF-P2TRIGGER-01` 怎么裁？

合格写法：

> 当前主动/回复触发频率公式已经实现，但默认参数尚未经过真实用户标定。
> A. 现在固定该值：可立即关闭 DEF，但以后可能重新调整。
> B. 保持实验状态，通过 dogfood / Eval 标定后再固定：不阻塞 Runtime 机制完成，但 Release 前必须解决。
> 推荐 B。请裁决 A/B。

（该条已于 2026-09-24 按 B 一侧裁定为"保留量级，押 Eval 标定"，此处只作为写法样本保留。）

## 5. 不走本协议的情形

- **Agent 职责范围内的技术判定**：修法唯一、判据已写、Owner 已派工的缺陷（例如"某处在 `MoveNextAsync` 未结束时 Dispose 异步流"这类缺陷），由 Owner 直接实施并按台账登记，不占用作者裁决额度。判断标准：**如果作者在这条问题上还有真实选择权，才提问；没有选择权却提问，是把工作量伪装成授权。**
- **紧急止血**：已发布链路正在损坏时先修后报，事后在同一轮台账里补写四部分。
- **纯信息同步**：验收判定、门禁读数、状态词变更属于告知，不属于裁决请求；不得用"待你确认"结尾把告知混充提问。

## 6. 传播与生效边界（不要误以为写在这里就够了）

`.gitignore` 第 28、29 行排除了 `/AGENTS.md` 与 `/PROJECT_PLAN.md`，因此**写在那些文件里的规则不随仓库传播**，新检出的 worktree 与 CI 看不到它们。本协议因此以本文件为权威文本：

- `AGENTS.md` 工作规则与 `PROJECT_PLAN.md` §6 只放指向本文件的一行指针。
- 本文件已入库，随 checkout 与 worktree 分发；措辞变更走一次带 `docs:` 前缀的提交，并在 `PROJECT_PLAN.md` §9 追加记录。
- 与既有判据的关系：本协议只约束**提问形态**，不放宽、不替代任何验收判据（`docs/eval/minimal-loop-run-checklist.md`、`docs/phase1-platform-baseline.md`、`docs/phase2-runtime-contract.md` §8 各自权威不变）。"按协议重写措辞"不等于"改口径"。
