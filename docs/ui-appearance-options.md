# UI-024 外观自定义与空会话展示规格

日期：2026-09-14。依据：作者本轮三张界面标注图及后续自定义图片、图片与标语组合反馈。状态：设计规格已修订交付，新增功能尚未实现。

分工：前端补选项、状态和持久化接入，后端补必要契约；UI 设计方负责实际页面绘制、材质和布局实现及最终视觉验收。不要为了完成选项接入自行重画一套组件样式。

## 1. 已确认需求

1. 目前深色底面的区域要有分开的透明选项，让用户决定哪些区域透明，不能一次性强制所有区域透明。
2. 空会话不要继续以巨大实色卡片占据主界面。图片与标语独立选择、组合排列：软件 Logo 或自定义图片均可在下方搭配模型生成标语或自定义标语，也允许仅图、仅文字或全部隐藏。毛玻璃也是可选表现。此要求取代此前 Logo 与两种标语互斥的三模式方案。
3. 用户可以选择壁纸是否应用到主界面之外，包括设置和退出程序窗口。范围开关的文字明确使用 **“仅应用于主页面”**。
4. 外观设置自身也要重新整理视觉结构，不能继续把越来越多的滑杆顺序堆在大卡片里。

以下尺寸、分组、默认迁移和失败表现是设计方案，不是作者逐项指定的参数；接口字段名需由前后端冻结，不将本文作为已经存在的 API。

## 2. 外观设置布局

```text
外观                              [效果预览]
  主题与颜色                       当前页/主页面切换预览
  壁纸与应用范围                   展示未保存草稿效果
  区域材质
  空会话展示
                                  取消    保存设置
```

右侧是设置内容区中的预览，不替代现有左侧设置导航。宽窗时表单和预览并排；窄窗改为顶部可展开预览、下方单列设置。保存区固定，内容独立滚动。复用 PryUi 与共享样式，标题 18、标签 13、间距 8/12/16/24。

### 主题与颜色

保留跟随系统、浅色、深色和自定义强调色。不强制重置用户现有颜色。

### 壁纸与应用范围

- 图片预览和选择/清除入口放在同一分组，预览与实际裁切规则一致。
- 开关文案：**仅应用于主页面**。
- 开启：壁纸用于“陪伴”主页面；角色、记忆、表情、设置及独立确认/退出窗口采用主题背景。
- 关闭：上述应用自绘页面与窗口也使用当前壁纸。主页面与设置页使用同一已保存外观配置；系统文件选择器、Windows 通知等系统拥有的界面不在范围内。
- 独立退出窗口按自身尺寸裁切同一壁纸，不能透视出窗口背后的其他软件，也不能把主窗口的聊天内容截图当背景。
- 保留图片透明度、背景遮罩、壁纸模糊，滑杆旁显示数值。壁纸透明度和区域底面透明度是不同属性，控件名称必须区分。
- 建议旧配置缺少范围字段时保持“仅应用于主页面”开启，避免升级后突然改变所有页面；用户可显式关闭。

## 3. 分区域材质

### 区域清单

| 设置项 | 作用区域 |
|---|---|
| 顶部应用栏 | 品牌、全局导航、窗口按钮所在底面 |
| 历史侧栏 | 历史列表/抽屉整体底面 |
| 角色信息区 | 当前角色头像、名称与切换入口底面 |
| 角色消息 | 助手消息及其元信息阅读底面 |
| 我的消息 | 用户消息及其元信息阅读底面 |
| 输入区 | 输入、附件、操作与状态提示的整体底面 |
| 管理页面 | 角色、记忆、表情、设置等页面的大背景底面 |
| 内容分组 | 管理页面中的表单分组、模型库和互动配置底面 |
| 菜单与弹出面板 | 角色动作、角色选择、表情选择、上下文菜单底面 |
| 独立弹窗 | 确认、退出等应用自绘窗口底面 |

空会话展示底面在其专属分组独立配置，不与所有消息共用。需要取消管理页背景遮挡才能看见下方壁纸；不能只让最内层卡片透明却保留不透明父容器，造成滑杆“无效”。输入框与按钮的承载色跟随所属区域统一设计，保留其操作状态，不为每个按钮再塞一套外观选项。

### 每项控件

- “启用透明”开关，独立保存。
- 开启后显示“底面透明度”滑杆和数值：0% 为完全实色，100% 为完全去除该底色。内部若使用不透明度，适配层明确换算，不能颠倒用户理解。
- “毛玻璃”可选项，开启后显示局部模糊强度。没有透明时禁用并解释依赖；不能由旧的“增强聊天背景氛围”隐式控制所有区域。
- 一项的变更不能修改其他项。浅深色主题共用用户选择的透明程度，颜色仍由主题语义 Token 决定。
- 默认保留已有外观，不自动把全部区域设为透明。恢复默认仅修改设置草稿，保存后生效。

### 绘制要求

1. 透明只作用于区域的背景层。禁止通过设置整个控件树的 Opacity，让正文、头像、图标、输入光标和焦点框一起变淡。
2. 毛玻璃模糊的是该区域背后的应用壁纸采样，区域内文字与控件保持清晰。给整个面板加 BlurEffect 不等于毛玻璃。
3. 材质模式不改变消息内容宽度、头像位置、侧栏尺寸、输入命中区或键盘导航；透明区域不变成鼠标穿透窗口。
4. 同一窗口复用背景资源与模糊结果；不要为每条消息逐帧抓取屏幕或生成整窗位图。
5. 完全透明由用户选择时不暗中恢复大实色卡片。预览可提示复杂壁纸的可读性变化，提供恢复默认；必要文字保护保持轻量，并与高对比度优先规则一致。
6. 无壁纸时透出主题画布，不能出现黑块、上个角色壁纸或未初始化内容。图片失败不影响表单、消息与关闭操作。
7. 选中、Hover、Focus、Disabled 和危险操作仍明确。不能因隐藏底色就让当前会话或焦点失去识别。

## 4. 空会话展示

### 独立内容来源

同一设置分组提供两组选项，预览展示组合结果；不能用一个互斥选择器在图片与文字之间切换。

| 设置 | 选项 | 内容及操作 |
|---|---|---|
| 图片来源 | 软件 Logo / 自定义图片 / 隐藏 | 软件 Logo 使用正式品牌资源；自定义图片支持选择、替换、清除及预览，自定义 Logo 也走此入口 |
| 标语来源 | 模型生成 / 自定义文字 / 隐藏 | 模型生成提供“生成一句 / 换一句”及请求状态；自定义文字包含主文案和可选副文案 |

两个来源、图文布局和底面材质独立保存。切换或隐藏任一部分不清空另一部分，也不丢失已保存的自定义图片引用、文字或生成结果。明确清除图片只解除该图片引用，不清除标语、头像或壁纸。

### 组合布局与尺寸

```text
           软件 Logo / 自定义图片
                 图文间距
                  主标语
               可选副文案
```

- 默认上图下文、整体居中。软件 Logo 下方同样可以显示标语；图片与文字作为一组定位，不拆成两块大卡片。
- 提供图片显示尺寸和图文间距调整，预览同步反馈；建议图文间距默认 16 DIP。完整字标建议宽 200～280 DIP，单字标约 112～160 DIP；自定义图片最长边建议默认 200 DIP。具体范围由前后端冻结并按可用窗口约束。
- 图片默认等比完整显示，可选择裁切填充；预览必须呈现实际裁切效果，不拉伸变形。透明图片按受支持的媒体格式保留透明区域。
- 内容区建议最大宽 360～400 DIP，主标语 22～24、副文案 13～14。模型标语以一句短文案、约两行主展示为目标；自定义文字支持中文、换行和长文本，正式长度约束由契约明确。
- 仅图、仅文字时隐藏部分及图文间距不占位；两者均隐藏时不保留空卡片。空白副文案也不保留高度。
- 窄窗或矮窗压缩图片和留白，文字按可用宽度换行，展示区必要时可滚动；不覆盖输入区或挤掉发送操作。

底面选项：**无底面 / 毛玻璃 / 实色**，统一承载图文组合。实色仍可保留，但缩小留白；选择图片、标语或材质均不能覆盖其他区域的透明设置。

### 自定义图片与迁移

- 空会话图片独立于聊天壁纸和角色头像，使用受管媒体上传与稳定资源 ID，不持久化用户本机文件路径。文件类型、大小及尺寸限制读取服务端媒体策略，不在前端另写一套常量。
- 选择、上传或解码失败时保留原图与文字，说明失败并允许重试；不破坏当前组合。保存前只更新设置草稿，取消恢复原配置。
- 新图片上传与配置绑定的生命周期由前后端明确：保存成功后引用才生效；未采用上传的保留与清理由后端负责，不能误清理仍被配置引用的图片。
- 旧固定文案迁移为自定义标语、图片来源默认隐藏，保持原文不丢失，不强制增加 Logo。若已有旧三模式配置，Logo 模式迁移为软件 Logo＋隐藏标语，文字模式迁移为隐藏图片＋对应标语来源；用户随后可自行组合。

模型标语需要单独冻结生成契约与行为：

- 建议首版由用户显式请求生成，不因每次打开页面、调整窗口、切换标签就重新加载模型或重复生成。
- 后端决定模型选择、当前角色上下文、取消、缓存和错误语义；不能把普通聊天回合接口或主动话题消息接口当作标语生成接口。
- 返回标语展示数据，不能产生用户/助手聊天消息、未读、通知或长期记忆副作用。
- 生成中保留已有展示，切换角色或退出页面后的迟到结果不得覆盖新角色；失败保留旧结果，提供重试。
- 首次无结果时明确显示尚未生成；没有生成能力时说明未就绪，不能静默换成固定句子并标为“模型生成”。

## 5. 接入边界与顺序

UI-024 初次交接时核查：现有 ClientThemePreferences 提供主题、强调色、UseGlassEffects、壁纸遮罩/透明度/模糊等；尚无本文完整的分区域材质、范围开关和空会话图文组合配置，也没有标语生成专用契约。接手时核对最新实现，不把本规格当成已有 API。

1. 前后端先冻结外观字段、默认迁移、取值范围、完整读取投影和保存原子性。沿用现有设置聚合入口，不建立前端私有配置文件绕过后端。
2. 前端补选项、依赖状态、草稿、保存/取消/重试及实时预览接线。不同区域使用稳定标识，不靠当前中文标签或控件名称持久化。
3. 空会话契约分别描述图片来源、媒体引用、显示尺寸与适配方式、标语来源、自定义主副文案、图文间距和底面材质；字段名不是本文冻结的 API。模型生成结果的存储、角色归属与缓存另由生成契约明确。
4. UI 设计方负责外观页重排、分区域背景绘制、共享毛玻璃材质、空会话图文组合和跨窗口一致性。功能接线提交后逐项实机验收，避免再出现“加了功能但各自一套视觉”。
5. 软件 Logo/自定义图片＋自定义标语、独立隐藏及区域设置可以先形成完整闭环；模型生成标语按专用契约单独接入，不伪造能力。

## 6. 验收清单

- 分别调整任一区域，其他区域不变；保存、退出重进、浅深主题切换后值与效果一致。
- 所有文字、头像、图标保持清晰，100% 底面透明仍可点击、输入、滚动和操作键盘焦点。
- 壁纸范围开关开启/关闭分别检查主页面、设置、角色、记忆、表情、动作面板和退出窗口；默认值和标签“仅应用于主页面”一致。
- 检查嵌套容器不残留不透明底面；独立窗口只用应用壁纸，不抓取桌面或其他窗口内容。
- 空会话按图片三选项×标语三选项逐项验证组合，软件 Logo 和自定义图片均能在下方搭配标语；两部分可独立隐藏、保存、重启恢复，切换不丢已配置内容。
- 自定义图片选择、替换、清除、上传失败与取消均可验证；不改变壁纸或头像，不因清除图片而删除文字；完整显示/裁切填充与预览一致。
- 图片大小、图文间距与材质调整互不覆盖；仅图、仅文字无多余占位，两者隐藏无空卡片。横图、竖图、透明图、长文案和 860×620 窗口均不遮挡输入。
- 毛玻璃不模糊正文，背景定位与原壁纸一致；无法提供材质时使用明确的透明着色回退，不宣称模糊已生效。
- 模型生成的正常/失败/取消/过期结果均可验证，历史、未读和长期记忆没有副作用。
- 外观预览与保存结果一致，取消恢复原状态；复杂亮/暗壁纸、浅深主题与系统 DPI 分别记录证据。
