# Pry 前后端边界审计与修正报告

日期：2026-09-06

适用分支：`agent/frontend-rebuild`

修正提交：`429e0ea fix: restore backend ownership of client policies`

## 结论

前端重构总体遵守了 API-003 边界：没有直接访问 SQLite、业务配置文件或模型进程，会话、消息、角色、记忆、贴纸、媒体和模型配置仍由后端负责。

审计发现的四处边界问题已经修正。前端可以继续开发，但必须以 `Pry.Client` 和 `docs/api-v1.md` 为唯一稳定调用边界，不应复制后端策略常量或通过磁盘路径判断后端资源状态。

## 已修正问题

### 1. 附件策略不得硬编码

原实现允许前端草稿容纳 12 个附件，而后端每回合只接受 6 个。用户选择 7～12 个文件时会先完成上传，随后提交回合失败。

现在桌面启动时调用：

```http
GET /api/v1/media/policy
```

前端使用响应中的：

- `warningThresholdBytes`：达到该值时在上传前提醒用户；
- `maximumBytes`：当前为 `null`，表示没有应用层单文件硬上限；
- `maximumAttachmentsPerTurn`：每回合允许引用的附件数量。

前端可以提前限制选择数量和显示提醒，但后端仍会执行最终类型、内容签名、数量和资源用途校验。

### 2. 语音模型状态只能来自后端

前端不得检查 `model.int8.onnx`、`tokens.txt` 或任何后端模型目录。模型路径不会通过 API 返回，这是刻意设置的安全边界。

开始录音前应读取：

```http
GET /api/v1/speech/models
```

仅当所选模型存在且 `available: true` 时允许开始录音。`custom` 只用于决定是否显示编辑和删除入口，不能作为可用性判断。

### 3. 客户端校验只是交互提示

后端现在会最终校验：

- 快捷键语法、重复修饰键和不同操作间的快捷键冲突；
- 最少/最多回复数量及其大小关系；
- 单条消息字符范围；
- 等待时间、打字速度、随机度及最短/最长延迟关系；
- 桌宠缩放范围；
- 主题、模型调参和其他既有约束。

前端的 `SettingsDraftService` 可以保留同类检查，以便立即标记表单错误。但不能假设请求经过该服务后一定合法，也不能吞掉后端返回的 `application/problem+json`。

字段错误应优先使用 Problem Details 的 `field`、`code`、`detail` 和 `traceId` 定位。不要把所有错误统一显示为“保存失败”。

### 4. “保存全部设置”使用聚合接口

设置窗口的主保存按钮必须使用：

```http
PUT /api/v1/settings
```

请求包含：

```json
{
  "preferences": {},
  "appearance": {},
  "models": {}
}
```

后端会先验证偏好、媒体引用和模型选择，然后只写入一次偏好并重载运行时。任一部分验证失败时，三部分配置都不会应用。成功响应包含最终的 `preferences` 和 `models` 投影，前端应使用响应刷新本地展示状态。

以下接口仍然保留，适合明确的单项操作：

- `PATCH /api/v1/preferences`：切换当前会话、角色或单独更新用户资料；
- `PUT /api/v1/appearance/media`：只修改背景或头像；
- `PUT /api/v1/models/selection`：只切换模型或调整模型参数。

用户资料窗口是一个同时修改资料和头像的窄范围用例，必须调用 `PUT /api/v1/user-profile`。该接口会在媒体引用或资料校验失败时保持两者原值；不要依次调用偏好与外观接口。

不要在一个“保存全部设置”动作中依次调用这三个接口，否则中途失败会重新产生部分保存。

## 前端职责

前端可以负责：

- Avalonia 控件、布局、主题预览和窗口生命周期；
- 文件选择器、录音采集和发送前预览；
- 未发送文字、附件草稿和会话切换时的临时 UI 状态；
- 根据 API 投影渲染会话、角色、贴纸、媒体和模型状态；
- 提前校验并友好展示后端 Problem Details；
- SSE 断线重连、序号续传和过期 UI 请求抑制。

前端不得负责：

- 直接读取或修改 SQLite、角色卡 JSON、偏好文件或贴纸清单；
- 启动、探测或停止模型进程；
- 读取后端模型目录、API Key 或内部媒体路径；
- 决定附件数量、允许类型等服务端策略常量；
- 持久化助手消息、长期记忆或倾听提示；
- 仅依靠客户端校验执行权限、资源归属或数据一致性判断；
- 使用多个写接口模拟一个要求原子性的业务操作。

## 合并与回归要求

合并 `429e0ea` 后至少执行：

```powershell
dotnet build Pry.slnx -c Release
dotnet test Pry.slnx -c Release --no-build
git diff --check
```

人工回归清单：

1. 后端策略为 6 个附件时，第 7 个附件在草稿阶段被阻止；大文件仅提醒、不拒绝。
2. 不可用语音模型不能开始录音，提示中不暴露模型路径。
3. 冲突快捷键、最少回复数大于最多回复数、最短延迟大于最长延迟时，后端返回 400。
4. 设置聚合请求包含无效模型时，用户资料、主题和外观均保持原值。
5. 设置保存成功后使用服务端响应刷新模型选中状态，不依赖提交前的本地候选值。
6. 切换会话、角色和单独修改用户资料仍可使用对应的单项接口。

## 已知后续事项

媒体上传与设置应用是两个请求。若媒体上传成功但设置最终未引用该资源，该资源可能暂时成为孤立媒体。前端不应擅自删除，因为资源可能被其他操作引用；后端需要在确定保留周期后提供未引用媒体清理策略。

完整字段和错误语义以 `docs/api-v1.md` 为准。如果实现与文档不一致，应先停止复制现有行为并向后端确认契约。
