# Pry 品牌与 UI 设计基线

日期：2026-09-12。任务：UI-018。性质：品牌方向与待实施的视觉规范；参数是初始设计建议，不代表当前界面已经实现或通过视觉验收。

## 1. 产品与设计目标

Pry 是以普莱为核心的本地虚拟陪伴助手，当前面向 Windows 10/11 桌面，提供 Messenger 与 Card 两套 Avalonia 窗口。核心场景是持续对话与陪伴；角色、记忆、模型和语音设置为辅助任务。用户画像的进一步细分尚无研究依据。

作者确定的优先级：现代感高于科技感，陪伴感高于工具感，角色归属感高于通用 AI 属性。界面应让用户先看见当前角色与对话，再看见操作，最后才是运行信息。

普莱提供情感主体：紫色、柔和优雅的轮廓、猫耳与发箍的品牌记忆。菲斯提供构造感：规则网格、明确对齐、清晰切面与蓝紫/黄色的强调关系。两者共同的四角星表达联系与回应。

猫耳保留在 Logo 内；按钮、窗口和气泡不机械复制猫耳。几何感通过布局和一致尺寸表达。四角星属于品牌符号，不作为通用 AI 功能图标。

## 2. 参考与素材边界

本轮查看了根目录 Sample 中的单字 Logo、完整 Logo 预览以及普莱、菲斯人设参考。Sample 是作者提供的本机参考目录，不是正式应用资源目录。

- 两个角色的服装尚未定稿。服装轮廓、蓝色面积、饰边、武器和配件不能成为固定 UI 规范，也不能直接作为默认头像、立绘或发行资源。
- 单字标负责小尺寸身份、系统图标和有限的品牌落点；完整字标负责启动、关于等具有足够空间的品牌表达。
- 两份 Logo 参考的主体色视觉上存在紫色与偏蓝紫的差异。保留原图色彩；下文 UI 色值为衍生建议，并非作者确认的 Logo 标准色或精确取色结果。
- 四角星原则上每个独立视图只设置一个主要品牌落点；已有 Logo 的星形计入视觉权重。聊天正文区不重复铺星形纹理。
- 原创图像遵守根目录 ASSETS_LICENSE.md 与 FAN_CONTENT_POLICY.md；普通技术文档与界面代码遵守项目代码许可。

## 3. 当前问题与证据边界

以下为源码检查结果，尚未进行本轮运行截图验收：

| 检查项 | 当前证据 | 设计影响 |
|---|---|---|
| 强调色分散 | App.axaml 定义 #B148C6，Messenger 局部样式定义 #6C63FF | 两套界面存在品牌表达漂移风险；实施时还需检查运行时主题覆盖 |
| 圆角分散 | 全局按钮为 8、输入框为 10；Messenger 按钮为 11、导航为 15、列表为 14 | 同级组件缺少稳定的尺寸规则 |
| 主按钮反馈 | 全局 primary 悬停复用普通按钮 Hover 背景 | 需核查悬停是否削弱主操作识别及文字对比 |
| 图标来源混合 | Messenger 同时使用 PathIcon、Segoe Fluent Icons 与字符符号 | 描边、填充和光学尺寸可能不一致 |
| 品牌与内容竞争 | Messenger 定义 420 DIP、透明度 0.075 的默认 Logo 背景 | 需在长对话、浅色主题和背景图片下检查正文干扰，不能仅凭透明度判断 |

## 4. 页面结构与视觉层级

Messenger 保留导航、会话列表、对话区的现有结构。一级信息是当前角色和正在阅读的消息；二级是会话名称与摘要；辅助信息包括时间、计数与快捷键。发送是编辑区主操作；新建会话采用次级表达，避免与发送、选中导航同时形成多个强色块。

对话区优先使用连续背景和留白，消息按发送者对齐。助手消息采用中性表面，用户消息采用低饱和紫色表面；不要用整块高饱和紫色承载长正文。已有气泡宽度和滚动行为先保留，只有发现可复现阅读问题时再调整。

Card 保留紧凑陪伴窗口的布局特征，与 Messenger 共用字体、颜色语义和交互状态。避免为了形式统一把它改成缩小的三栏界面。

设置使用分组标题、说明与控件建立层级。默认按留白分组，只有可独立操作或具有独立状态的模块使用卡片。模型和连接错误必须保留清楚的文本反馈，不能用品牌装饰掩盖。

## 5. 色彩 Token 初稿

大面积使用略带紫调的中性色，紫色负责操作与选中，黄色只负责少量品牌焦点。品牌黄与警告色使用不同 Token；警告始终配合图标和文字。

实施时验证实际文字与背景组合：正文目标对比至少 4.5:1，关键控件边界与焦点目标至少 3:1。以上为项目验收目标；本轮未测量这些候选色的全部组合。黄色不用于白底小字。自定义背景下正文必须有稳定的底色承托，不能依赖图片恰好足够暗。

复用现有 PryCanvasBrush、PryPanelBrush、PryTextBrush、PryAccentBrush 等资源作为迁移入口，不建立与运行时主题并行的第二套颜色权威。保留用户已有自定义主题选择；品牌默认调整不能静默覆盖用户配置。

## 6. 字体、间距与组件规范

尺寸统一使用 Avalonia 逻辑单位 DIP。中文优先 Microsoft YaHei UI，拉丁与数字可使用 Segoe UI，并配置系统无衬线回退；正文不使用 Logo 字形或图标字体。实现后核查中英文混排行高。

| 字体层级 | 字号 / 行高 | 字重 | 使用范围 |
|---|---|---|---|
| 页面标题 | 22 / 30 | SemiBold | 设置、角色等页面标题 |
| 区域标题 | 18 / 26 | SemiBold | 当前角色、主要分组 |
| 消息正文 | 15 / 24 | Regular | 连续阅读 |
| UI 正文 | 14 / 22 | Regular | 表单、列表、按钮；标签可用 Medium |
| 辅助文字 | 12 / 18 | Regular | 时间、说明；错误解释不缩成小字 |

间距采用 4、8、12、16、24、32、48；区域内优先 8/12，区域间优先 16/24，页面边距默认 24、紧凑窗口 16。圆角采用 4、8、12、16、Full：小标记 4，按钮与输入框 8，菜单与消息容器 12，独立弹窗 16，头像 Full。系统标题栏控件可保留直角。

| 组件 | 初始参数 | 规则 |
|---|---|---|
| 标准按钮 | 最小高 36，水平内边距 16，图文间距 8 | Primary 实色；Secondary 柔和底；Tertiary/Ghost 透明底；Danger 使用错误语义 |
| 图标按钮 | 默认 36×36，图形 20×20 | 必须有 Tooltip 和可访问名称；触控场景目标至少 44×44 |
| 输入框 / Select | 最小高 40，内边距 12,8，边框 1 | 多行内容允许增高；Label 独立存在，Placeholder 不替代标签 |
| 会话列表 | 默认最小行高 64，内边距 12 | 名称优先，摘要可省略；字号放大时允许增高；选中同时使用底色和位置标记 |
| 弹窗 | 内边距 24，分组间距 24 | 阴影仅表达浮层；长内容内部滚动，操作区保持可达 |
| 图标 | 统一 24 单位网格、约 1.75 单位描边 | 普通操作统一线性风格；Logo 独立使用原始品牌形状 |

字体、间距和圆角参数需要形成共享资源。图标规范为目标，不能仅将现有填充 Path 加描边；逐项核对形状及 Windows 字体回退后替换。

## 7. 状态规范

- Default：主次操作清楚，导航选中可辨认。
- Hover：同一色相内改变明度；普通按钮采用低强度底色，主按钮保留主操作身份。
- Pressed：进一步改变明度，避免缩放引发布局移动。
- Focus：键盘焦点使用 2 DIP 可见轮廓，不能只有轻微色差；选中与焦点可以同时呈现。
- Disabled：使用独立的中性前景和底色，移除交互反馈；必要时在附近说明不可用原因。
- Loading：保留按钮尺寸，显示进度及“正在发送”等文字；确有取消能力时显示停止操作，不能伪造进度百分比。
- Error：定位相关输入或消息，配说明及实际可用的重试/修改入口；持久错误不只用 Toast。
- Empty：说明当前为空及下一步，例如“还没有对话”“开始新对话”；品牌图只作为次要落点。
- Selected：背景与文字/位置标记共同表达，避免把每个选中项都做成主按钮。

轻量颜色过渡建议 120–160 ms；系统减少动画时关闭非必要过渡。四角星不持续旋转、闪烁或发光。

## 8. 尺寸适配与验证

当前平台以桌面窗口和 DPI 适配为准。Messenger 源码默认 1180×780、最小 920×620；初期保留这些边界，验证导航、侧栏与输入区不挤压正文。宽窗口优先增加外侧留白；窄窗口沿用已有侧栏收起入口，不简单等比缩小字号或点击区域。

移动端尚无实现范围。若未来支持，应另行设计单列页面、返回导航、键盘与安全区域；本规范不宣称已经实现移动适配。

界面实施后记录模式、主题、逻辑尺寸、DPI、操作与结果，覆盖：

1. Messenger / Card，浅色 / 深色，100% / 150% / 200% DPI。
2. 最小窗口、默认窗口、最大化；中文长名称、中英文混排、多行消息、长链接与放大字号。
3. 键盘 Tab 焦点、悬停、按下、禁用、选中、加载、取消和失败重试。
4. 自定义背景、主题预览与取消回滚；Logo 小尺寸清晰度与正文对比。

本轮只交付设计文档。界面截图、对比度测量及交互回归属于实施任务的完成条件，不能用本文档替代。

## 9. 实施顺序与风险

先统一颜色资源及主按钮状态，再收敛字体、间距与圆角，然后逐项统一图标，最后判断水印是否需要调整。每一步只解决已确认的问题，保留会话、设置与窗口模式的业务行为。

主要风险：深紫 Logo 在暗背景上辨识不足；黄色与白底对比不足；运行时主题覆盖 XAML 导致状态不一致；统一尺寸后紧凑窗口密度下降；未定稿服装被误当正式品牌资产。通过背景适配、实际对比测量、统一主题入口、最小窗口验证和明确资源边界处理。
